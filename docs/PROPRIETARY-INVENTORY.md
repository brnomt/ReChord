# ReChord — Proprietary & Binary Inventory

> The authoritative map of "what is still third-party/binary" in a ReChord
> firmware image, vs. what is genuinely our source. Answers the recurring
> question *"what else is still FiiO / binary?"*
>
> Status: **documentation only** (decision of 2026-08 — we are not replacing
> codecs/resources/bootloader this milestone, just recording the boundary).

---

## TL;DR

A flashable `HIFIEC*.IMG` is **not** all ours. It is a layered artifact where
only the middle layers (fw1 code, section_3 code) are rebuilt from source; the
outer layers (mask ROM, bootloader, resources) are preserved binary blobs, and
the codec math is linked from Rockchip prebuilt `.lib` archives. The full
from-source goal is therefore **not yet met** — this doc is the honest ledger.

## The full image, layer by layer

| Layer | IMG offset / address | Owner | Origin | Replaceable? |
|---|---|---|---|---|
| **Mask ROM** (boot) | `0x00000000–0x02FDFFFF` | Rockchip | Silicon mask | ❌ **Never** — fixed hardware "BIOS" |
| **ROM API (HAL)** | `0x02FE0000–0x02FFFFFF` | Rockchip | Silicon mask | ❌ **Never** — invisible; we *call* it (I2S/DMA/LCD/GPIO) |
| **fw1 header + memory-map table** | `0x0001F8–0x0007B8` | FiiO/Rockchip | Container | ⚠️ Regenerated by `pack_fw1.py` |
| **fw1 (AP) code** | `0x0007B8–0x00057820` | **ours** | RKnanoD SDK (leaked) + `rechord_*` | ✅ Built from source |
| **sec2 bootloader** | `0x00057820–0x00081A14` | Rockchip/FiiO | Binary | ⚠️ Preserved; validates fw1/fw2, jumps to `firmware_entry` |
| **section_3 (BB) code** | `0x00081A14–0x009BAA0E` | **ours** | RKnanoD SDK (leaked) + `rechord_*` | ✅ Built from source |
| **ROCK26IMAGERES** (UI assets) | `0x009BAA0E–0x01FC13F6` | FiiO | Binary | ⚠️ Preserved: 1617 bitmaps + fonts (cassette skin) |
| **End marker + padding** | `0x01FC13F6–0x02000000` | FiiO | Binary | ⚠️ Preserved |
| **EOF trailer** | `0x02000000` (`0x1EA1C309`) | FiiO | Constant | ⚠️ Preserved (not a CRC of content) |

## Codec / DSP `.lib` archives (Rockchip prebuilt)

These are linked as binary ARM archives; their source is **not** in the repo
(the community SDK leak ships them as `.lib`, not `.c`):

| Category | `.lib` files | Status |
|---|---|---|
| Audio codecs | MP3, FLAC, AAC, APE, ALAC, OGG, WAV, DSF, DSDIFF | ⚠️ binary, linked |
| Image codecs | JPG, BMP | ⚠️ binary |
| Bluetooth | LwBT (4 versions) | ⚠️ binary |
| DSP/effects | Spectrum, Fade, **EQ** | EQ → ✅ **replaced** by `rechord_dsp.c`; Spectrum/Fade still binary |
| Misc | MyRandom (shuffle), SSRC (resample), NS (noise), SBC, MP2, AVI | ⚠️ binary |

> 32 `.lib` archives total under `community/sdks/.../Common/Codec/`. The EQ
> (RkNano_EQ_24BIT) is the first and so far only one replaced from source.

## What is genuinely "ours" (from-source, no third-party origin)

- `firmware/rechord_app.c`, `rechord_win.c`, `rechord_dsp.c/.h`, `bb_stub.c`,
  `fault.c`, `stubs.c`, `entry_stubs.S`, `config.h`, `ipc.h`,
  `rechord_version.h` — the ReChord application layer.
- `tools/pack_img.py`, `tools/pack_fw1.py`, the Makefile, linker scripts —
  build & packing tooling.

## Important caveat — the SDK itself

`firmware/rockchip/` is the **leaked Rockchip RKnanoD MP3 SDK v1.3
(2016-11-02)**. It is *source code* and we compile it, but it is
**third-party-origin** (Rockchip proprietary, distributed via a community
leak), not clean-room code. Treat it the same way as the `.lib`s for
licensing purposes — it is not redistributable under our terms just because
it's in `.c` form.

## What this means for the project goal

The README's "complete from-source firmware" goal is **partially met**:

| Goal layer | Status |
|---|---|
| AP (UI) + BB (audio) code | ✅ from source (on top of the leaked SDK) |
| DSP/EQ | ✅ from source (`rechord_dsp.c`) |
| Codec decode math | ❌ Rockchip `.lib` binaries remain |
| UI bitmaps / fonts / skin | ❌ FiiO `ROCK26IMAGERES` binary remains |
| Boot ROM + HAL | ❌ silicon mask ROM (unavoidable, never replaceable) |
| Bootloader (sec2) | ❌ binary (could theoretically be reimplemented — not attempted) |

## Gitignore status (what's local-only vs. committed)

Local-only (`.gitignore`): `stock/` (copyrighted IMGs), `community/` (leaked
SDKs + TRM/datasheet PDFs + rkbin/rkdeveloptool), `build/`.

Committed: all of `firmware/` source, `docs/`, `tools/`.
