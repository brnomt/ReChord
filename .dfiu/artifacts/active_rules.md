# Active rules: ReChord

- [blocker] `R-8cd5fb0eb24a` (AP (fw1) .bss layout / linker script / image geometry): Never link the AP image with _bss_end above 0x0304A000; FW_RAM length is 0x46000 and the linker enforces it. -> Before adding statics to the AP, check _bss_end; reclaim RAM (union the mutually-exclusive big buffers: FLAC pool / USB-MSC chunk / fw_update staging) instead of raising the ceiling.
- [warning] `R-e9b5d8222673` (AP<->BB mailbox reply paths): Any mailbox reply (even DEC_OPEN_ERR) breaks the AP's wait; silence is the only deadlock. -> Guarantee a reply for every mailbox command path, including error answers; treat any silent command as a deadlock.
- [warning] `R-3f66ea5d12c8` (firmware/services, firmware/ui/screens): A module reading shared state owns acquiring and releasing it, and its test enters through the same door production does: a test that pre-acquires that state hides lifecycle bugs. -> When a screen shows 'empty' while the data is known good, check who opens the shared state first. Never pre-acquire state in a test that the code under test should acquire.
- [warning] `R-7cd6518a7e7b` (firmware/startup (link seams)): A feature must not depend on a weak symbol that lacks a strong implementation: check the linked ELF for W symbols in that subsystem before trusting the feature. -> Run arm-none-eabi-nm on the CFW ELF and confirm every remaining weak symbol is an intentional fallback before handing a build over for hardware test.
- [warning] `R-e68bf2428377` (firmware/startup, firmware/services/input.c): A safety net that hides a broken dependency is a bug amplifier: when a fallback triggers, make it observable (log/counter) so the real failure cannot masquerade as a tuning problem. -> When adding a fallback for a hardware/OS dependency, log the first time it engages (once, not per pass), and verify the dependency on hardware before tuning anything that depends on it.
- [blocker] `R-e9e18de6c692` (fw1 scatter/loader model (tools/make_fw1.py)): Scatter row src addresses live in the loaded RAM image, not XIP; verify byte-for-byte against the reference image before flashing. -> Validate every scatter row against the reference fw1 boot model before any on-device flash.
- [blocker] `R-9461aeaecbe2` (tools/pack_fw1.py fw1 scatter table): Never flash a custom fw1 until the scatter table is validated; no scatter row may target 0x03000000..0x03004000. -> Keep the pack_fw1.py safety gate; require scatter-table review + reference-image diff before any fw1 write.
- [blocker] `R-1f1c5d829375` (tools/pack_img.py section_3 flash region): Never zero-fill the stock section_3 tail; the AP reads string/pointer tables from inside that region. -> Keep --keep-stock-tail as default; byte-diff the section_3 tail against stock after every repack.
- [blocker] `R-9f6e141101cb` (update image format: outer header + fw_end header copy (tools/make_fw1.py, tools/pack_img.py)): A valid update image must duplicate its first 512 bytes at offset fw_end (LE32 at 0x1F4) and carry the trailer CRC at (fw_end+0x104000)&~0xFFFFF. -> Always duplicate IMG[0:0x200] at offset fw_end = LE32(IMG[0x1F4]); byte-check it in the packer before flashing.
